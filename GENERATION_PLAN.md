## Ordering rationale

- Numbering follows the constitution's binding decision: phase 1.n is the kit ladder's Phase n, so every `TODO(phase-N)` marker maps one-to-one. No phase added, merged or renumbered.
- 1.0 first: the firewall is a t=0 decision (DK-1); the repo is public from its first push, so the audit must fail on the fixture before any extraction exists. The rules count and tree audit are already green at install; the phase's real work is the fixture proof, the Docker host and the first CI run.
- 1.1 before 1.2: the oracles and the load map read the extracted binaries; the manifest is what makes every later hash comparable and what the audit enforces.
- 1.2 fixes N. The disc has 105 `.BIN` files; which are code, which load at what address, and whether the `/BIN` debug/edit modules are part of the fleet is unknown until live memory proves it. Every later milestone says "N of N", so N is frozen at 1.2's close and any change to it goes through the critic.
- 1.2 also records forced boundaries (jump-table spans, per-file optimisation levels, interleaved library objects) so 1.3 segments before any C exists (DK-12); structure gets more expensive with every bank.
- 1.3 before 1.4: the all-asm baseline gives the probe harness a hash-checked build to link probes into, and makes every later change a before/after on a green fleet. Onboarding the whole fleet at 100% asm is mechanical once splat configs are generated from the load map; it is one phase, not per-binary phases.
- 1.4 before any campaign: a wrong compiler era or silent assembler default makes systematic near-misses (BFM retrospective). The pin is by evidence; the first matched functions prove the pipeline end to end.
- 1.5–1.7 are instruments built at 0%: in BFM nearly every wall was the project's own instrument. Census before multipliers (the multipliers consume the census's families and twins); multipliers before the codegen map (integration, not idioms, is the bottleneck); the map and permuter last because they serve the hard tail the multipliers leave.
- 1.8 stays one phase in the ladder's shape; planner-phase gives it tasks in waves. Its opening task is the manual wave, whose measured bank rate sets routing and wave size. If that measurement shows the campaign exceeds a reasonable phase for one developer on a Pro plan, the 1.8 planner proposes splitting the campaign by binary set (main exe + shared engine, stage overlays, module overlays) through the critic; deciding the split before the rate is measured would be a guess.
- 1.9 before 1.10 per the constitution: publication proves reproducibility on a byte-complete tree; readability is enforced from the first bank, so 1.10 is names, pins and formatting only, and must keep N of N.

## Standing constraints

- The byte gate is the only claim: done = whole-binary hash green from a clean rebuild with the exit code read (G3, G61); a standalone or masked match is a filter, never a bank; no unmatched C in a default build.
- ROM firewall in every phase (G12): no game-derived byte, pasted disassembly or vendor SDK in any tracked file; `PY tools/audit_public.py` green before every commit that stages new file types; docs cite commits by date + subject.
- Never `git clean -x` (G18): the extraction, the RE database and `.run/` are ignored-but-present. Irreversible operations rehearsed on a scratch copy.
- The dump stays machine-local at `/Users/Shared/GameInputs/dino-crisis-2/usa/`; contributors bring their own.
- Builds, gates and harnesses run in the amd64 Docker host (source in a named volume, not a bind mount); the disassembler DB + MCP and the emulator run on the Mac host. An MCP server restart ends with a request to the developer to run `/mcp` (`docs/ops/disassembler-mcp.md`).
- Evidence over recall: every address in `docs/memory-map.md` with its datapoints; every name with a recorded basis (G62); the DC2 recomp and randomizer are not inputs. Inherited cookbook levers are hypotheses until re-proven on this game's bytes.
- Models: experts and coders on Opus 5.5; no task marked `effort: high`; deep judgments (compiler pin, load addresses, segmentation, wall verdicts) go to the developer's `/discuss max`, never Fable.
- Budget: Claude Pro. Free, local, deterministic work before paid; free tools preferred; any paid tool, licence or service is a developer decision raised through the plan, never assumed.
- Scratch under `.run/` only; cap 25 GB, warn at 20 GB; pruning is the developer's call. Disk is tight (28 GB free at generation).
- AI conduct: outward text (issues, PRs, releases, community messages) written by the developer; no automated traffic against community infrastructure. Agents never push.
- Numbers in published documents are generated by tools with a freshness check, never typed.
- Readability from the first bank: pins recorded at draft time, shared bodies as C, canonical types, formatter from the first C file, file layout from forced boundaries.
- The harness is not the product: defects in `tools/` PA3/kit scripts, `.claude/`, hooks, templates or agent files are `harness:` gotchas for the ProjectArchitect repo, never tasks here. Project tools (extractor, harnesses, census, publisher) are product and live beside them.
- Hand-offs are replayed, never summarised (G59).
