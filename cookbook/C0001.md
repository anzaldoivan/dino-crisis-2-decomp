# C0001 — The decomp idiom entry shape: residual, mechanism, lever, byte proof
tags: cookbook-format,idiom,residual,mechanism,lever,byte-proof · date: 2026-09-30 · phase/task: - · origin: decomp-architect

Every idiom entry in this cookbook is byte-proven on a named function and carries four parts:

1. **The residual** is what the diff looks like (the tell): the instruction, its position, the register, the count.
2. **The mechanism** says which compiler pass produces it and why, with the dump line that shows it. A verdict without
   a pass and a dump line is a hypothesis.
3. **The lever** is the C-level change that moves it, stated as a shape. A register pin is never the answer. A pin is
   a symptom. Before a lever enters the cookbook, strip it from the accepted body and recompile. About one credited
   lever in three is inert.
4. **The byte proof** is the function, the diff before and after, and the compilation the claim survived. The
   compilation is one of standalone / real translation unit / whole-binary.

Every entry has this pinned context. The toolchain triple is psyq4.6 `CC1PSX.EXE` (GCC 2.95.2) with maspsx
`--aspsx-version=2.86` (`docs/ops/compiler-pin.md` in the development repository, phase 1.4). The SDK evidence is
"Library Programs (c) 1993-1997 Sony Computer Entertainment Inc." in SLUS_012.79 (PsyQ 4.x era). Phase 1.2 detected
PsyQ 4.7 (`docs/ops/decomp-environment.md` in the development repository, "The oracles").

No one file records the calling convention and the register roles of the target. `docs/codegen-map.md` holds what the
bytes proved.

Tag each entry with its symptom words, so that `grep -i <symptom> cookbook/INDEX.md` finds it. The triage table entry
maps a tell to its mechanism and lever family.
