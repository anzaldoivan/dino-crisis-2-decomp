# A verify clause that reads extracted data must extract it itself

Milestone clauses run in order on whatever volume exists. A clause that reads extracted game data and relies on a
later clause (e.g. the fleet check) to extract it is green on a used volume and red on a fresh one. Make the tool
extract through the existing extraction path when its input is absent (and fail with a clear error if that fails),
then prove the clause on a fresh volume (`docker volume rm <vol>` is safe when it holds only the synced tree and
scratch). Phase 1.4 T9 did this for `tools/probe.py --pinned`.
