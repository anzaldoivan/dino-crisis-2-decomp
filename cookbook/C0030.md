# A verify clause that reads extracted data must extract it itself

Milestone clauses run in order on whatever volume exists. Take a clause that reads extracted game data and relies on
a later clause (e.g. the fleet check) to extract it. That clause is green on a used volume and red on a fresh one.

If the input of the tool is absent, make the tool extract through the existing extraction path. If that extraction
fails, make the tool fail with a clear error. Then prove the clause on a fresh volume. When the volume holds only
the synced tree and scratch, `docker volume rm <vol>` is safe. Phase 1.4 T9 did this for `tools/probe.py --pinned`.
