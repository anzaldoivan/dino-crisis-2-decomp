# C0005 — Breadth is isolated agents: per-item agents cost about linearly, one serial loop about quadratically
tags: breadth,agents,drafting,fan-out,cost · date: 2026-09-30 · phase/task: - · origin: decomp-architect

Drafting byte-exact C for N functions is breadth-shaped work. For such work, spawning one isolated agent per item is cheaper
than the main conversation doing them one after another. This holds even though it looks like N copies of the same prompt.

**Why:** the main conversation re-sends its entire growing context on every turn. So the conversation processes function N
with the disassembly, diffs and drafts of functions 1 through N−1 still in context. The cost grows roughly quadratically. Each
spawned agent gets a fresh, small context (its one function), and the cost is roughly linear. The agents run in parallel, so
hours become minutes. A measurement on the source project showed that forty functions serially cost several times what forty
isolated agents cost.

The redundant per-agent reading of shared documents is real but secondary.

**How to apply:** batch a few functions per agent, pre-filter the trivial ones, and trim what each agent reads. An inline idiom
cheat-sheet beats "read the whole cookbook". A measurement showed that more context was worse, not better.

The compile-and-hash gate is local and free. Only the drafting costs tokens. Fully model-free drafting hits a low ceiling, and
the model is what lifts it. Working a function by hand in the main loop wins only for a handful of high-value items. Past
that, accumulation makes it lose.
