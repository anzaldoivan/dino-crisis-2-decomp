# C0050 — Scaled index: x*4 / p[i] puts the index first in the addu (expand MULT-first swap); i<<2 keeps base first
tags: codegen-map,expand-cse,expand,fold,operand-order,address,mult,shift · date: 2026-10-02 · phase/task: 1.7/T5 · origin: -

tell: addu operand order in a scaled-index address: index,base vs base,index (same insns)
group: expand-cse

**The residual** — game fn `slus_012_79:0x800604F4` (reads an offset from a table at `base + 8` indexed by a signed
byte field, then a guarded byte store). Natural draft (`b + *(int *)(b + s->f9f * 4 + 8)`, also `((int *)(b + 8))[i]`
and `((int *)b)[i + 2]`) has the game's 17 insns, same registers, but the address `addu` has its operands swapped:
index register first, base second (word 7). Reproducer `tools/probes/levers/repro/expand_commute.c` (cc1 `.s`):
`com_a b + i * 4 + 8` → `sll $5,$5,2 | addu $5,$5,$4 | lw $2,8($5)`;
`com_b b + (i << 2) + 8` → `sll $5,$5,2 | addu $4,$4,$5 | lw $2,8($4)`; `com_c p[i + 2]` (int *p) = com_a.

**The mechanism** — expand, not cse: the order is fixed in `.rtl` and survives `.cse`, `.gcse`, `.cse2` and combine
unchanged. Pointer arithmetic `ptr + int` goes through pointer_int_sum (c-typeck.c:2654), which scales the int by the
pointee size with a MULT_EXPR (c-typeck.c:2726; array indexing goes the same way). expand_expr PLUS_EXPR
(expr.c:6904) expands that MULT under EXPAND_SUM into a `(mult ...)` rtx and at both_summands (expr.c:6995), line
7035 "Put a constant term last and put a multiplication first", swaps it to operand 0. A source `<<` is an
LSHIFT_EXPR: op1 is an `ashift`, not a MULT, so no swap and the base stays first.
- `com_a .rtl` insn 16 `(set (reg:SI 86) (plus:SI (reg:SI 85) (reg/v:SI 81)))` (85 = i<<2, 81 = b);
  `com_b .rtl` insn 14 `(set (reg:SI 85) (plus:SI (reg/v:SI 81) (reg:SI 84)))`; same insn in `.cse` for both.
- game-fn drafts: before `.rtl` insn 27 `(plus:SI (reg:SI 90) (reg/v:SI 82))`, after `.rtl` insn 25
  `(plus:SI (reg/v:SI 82) (reg:SI 89))`, both unchanged through `.cse`, `.gcse`, `.cse2`, `.combine`.
- A pointer temp (`int *o = (int *)(b + 8); b + o[i]`) also matched, but by another route: `.rtl`/`.cse` keep
  `(plus (reg 91) (reg 85))` index first, and combine re-forms the sum when it folds `85 = 82 + 8` into the address,
  emitting `(plus:SI (reg/v:SI 82) (reg:SI 91))`. That one is a combine effect; the shift lever is the expand one.

**The lever** — when an address `addu` (or any sum) has index and base swapped against the target and the index is a
scaled int, change how the scale is written: `i * 4` / `p[i]` → index first; `(i << 2)` added to a `char *` → base
first. Inverse: a game fn with index-first order wants `* 4` or array indexing. Only for a sum whose scaled operand
is a MULT in the tree; a plain `a + b` keeps source order (fold-const.c:4242 swaps constants only).

**The byte proof** — `config/levers.tsv` row `shift-scaled-index`: `tools/probes/levers/shift-scaled-index.before.c`
(`b + s->f9f * 4 + 8`) differs from the game at word 7 (addu operand order); `.after.c` (`b + (s->f9f << 2) + 8`, the
one changed expression) is byte-identical (relocation-masked) under the pinned triple;
`tools/codegen_map.py --check --groups expand-cse` → proven.
