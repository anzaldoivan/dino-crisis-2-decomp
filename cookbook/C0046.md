# C0046 — A late temp's v0/v1 choice follows local vs global ownership; reuse a user var to move it
tags: codegen-map,regalloc,local-alloc,global-alloc,v0,v1,temp-reuse,reg-substitution · date: 2026-10-01 · phase/task: 1.7/T3 · origin: -

tell: a late temp lands in $v0 where the game has $v1 (or the reverse), same insns, after the last call
group: regalloc

**The residual** — game fn `slus_012_79:0x8005ED34` (reads a 6-byte command record through `s->c`, calls two fns,
then advances `s->c` by one record, returns 0). Natural draft `s->c++;` differs from the game at three insns only
(words 18, 21, 22: the load/add/store of the bump): ours uses `$v0`, the game `$v1`; everything else, including
`move v0,zero` for the return, is identical. Reproducer `tools/probes/levers/repro/regalloc_temp_reuse.c` (our compile,
pinned triple): `reuse_a` (`s->c++`) → `addu $2,$2,6; sw $2,0($16)`; `reuse_b` (`c = s->c; c++; s->c = c;`) →
`addu $3,$3,6; sw $3,0($16)`.

**The mechanism** — which allocator owns the bump's pseudos (gcc 2.95.2: local_alloc → global_alloc).
- `s->c++` expands to fresh pseudos for the load and the sum; each is set once, dies once, in one block, so
  local-alloc owns it (local-alloc.c:364) and find_free_reg scans hard regs numerically (identity REG_ALLOC_ORDER,
  mips.h:1900) → first free is `$2`. `.lreg` of `reuse_a`: `;; Register 93 in 2.` / `;; Register 94 in 2.`;
  `.greg`: `;; 0 regs to allocate:`.
- `c = s->c; c++; s->c = c;` reuses user var `c`, now set 3 times ("set 3 times; user var; dies in 2 places" in
  `.lreg`), so local-alloc skips it and global-alloc allocates it once for its whole life. Its early life (`c->a`
  index into `s->t[]`) overlaps temps local-alloc already put in `$2`, so global gives it `$3`, and the late
  load/add/store inherit `$3`. `.greg` of `reuse_b`: `;; 1 regs to allocate: 82`, dispositions `82 in 3`.

**The lever** — when a late temp sits in `$v0` and the game has `$v1` (or another low reg), route the value through an
existing user variable whose earlier life already conflicts with `$v0` (`c = s->c; c++; s->c = c;` instead of
`s->c++`). The multi-set user var moves to global-alloc and keeps the register it got for its whole life. The reverse
(game `$v0`, ours a higher reg) suggests the original used a fresh temp or a direct `x->f++`.

**The byte proof** — `config/levers.tsv` row `reuse-user-var`: `tools/probes/levers/reuse-user-var.before.c`
(`s->c++;`) differs from the game at word 18; `.after.c` (the one changed statement) is byte-identical
(relocation-masked) under the pinned triple; `tools/codegen_map.py --check --groups regalloc` → proven.
