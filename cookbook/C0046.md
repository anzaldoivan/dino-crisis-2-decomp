# C0046 — A late temp's v0/v1 choice follows local vs global ownership, and a reused user var moves it
tags: codegen-map,regalloc,local-alloc,global-alloc,v0,v1,temp-reuse,reg-substitution · date: 2026-10-01 · phase/task: 1.7/T3 · origin: -

tell: a late temp lands in $v0 where the game has $v1 (or the reverse), same insns, after the last call
group: regalloc

**The residual** — the game fn `slus_012_79:0x8005ED34` reads a 6-byte command record through `s->c` and calls two
fns. Then it advances `s->c` by one record and returns 0. The natural draft `s->c++;` differs from the game at three
insns only (words 18, 21, 22: the load/add/store of the bump). Ours uses `$v0`, and the game uses `$v1`. Everything
else, including `move v0,zero` for the return, is identical. The reproducer
`tools/probes/levers/repro/regalloc_temp_reuse.c` (our compile, pinned triple) gives `reuse_a` (`s->c++`) →
`addu $2,$2,6; sw $2,0($16)` and `reuse_b` (`c = s->c; c++; s->c = c;`) → `addu $3,$3,6; sw $3,0($16)`.

**The mechanism** — the register depends on which allocator owns the bump's pseudos (gcc 2.95.2: local_alloc →
global_alloc).
- `s->c++` expands to fresh pseudos for the load and the sum. Each is set once, dies once, in one block, so
  local-alloc owns it (local-alloc.c:364). Then find_free_reg scans hard regs numerically (identity REG_ALLOC_ORDER,
  mips.h:1900), and the first free reg is `$2`. `.lreg` of `reuse_a` shows `;; Register 93 in 2.` /
  `;; Register 94 in 2.`, and `.greg` shows `;; 0 regs to allocate:`.
- `c = s->c; c++; s->c = c;` reuses user var `c`, which is now set 3 times
  (`set 3 times; user var; dies in 2 places` in `.lreg`). So local-alloc skips it, and global-alloc allocates it once
  for its whole life. Its early life (`c->a` index into `s->t[]`) overlaps temps that local-alloc already put in
  `$2`. So global gives it `$3`, and the late load/add/store inherit `$3`. `.greg` of `reuse_b` shows
  `;; 1 regs to allocate: 82` and dispositions `82 in 3`.

These are the kit regalloc levers (kit regalloc.md, gcc 2.7.2), translated to the 2.95.2 producer. The priority is
`pri = floor_log2(refs)*refs*size/live_length*10000` (local-alloc.c:1511 QTY_CMP_PRI, global.c:602 allocno_compare).
Local breaks ties by qty number (first birth, local-alloc.c:1535), and global breaks ties by pseudo regno
(global.c:615).

**The lever** — use this lever when a late temp sits in `$v0` and the game has `$v1` (or another low reg). Route the
value through an existing user var whose earlier life already conflicts with `$v0`
(`c = s->c; c++; s->c = c;` instead of `s->c++`). The multi-set user var moves to global-alloc and keeps the register
that it got for its whole life. The reverse (game `$v0`, ours a higher reg) suggests that the original used a fresh
temp or a direct `x->f++`.

**The byte proof** — the proof is `config/levers.tsv` row `reuse-user-var`.
`tools/probes/levers/reuse-user-var.before.c` (`s->c++;`) differs from the game at word 18. `.after.c` (the one
changed statement) is byte-identical (relocation-masked) under the pinned triple.
`tools/codegen_map.py --check --groups regalloc` → proven.
