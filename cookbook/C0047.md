# C0047 — If/else arm order: jump.c swaps an early-return then-arm last. Invert the test to lay it
tags: codegen-map,jump,block-order,branch-polarity,delay-slot,dbr,sched-reorg · date: 2026-10-02 · phase/task: 1.7/T4 · origin: -

tell: if/else arms in swapped order (early-return arm at fallthrough vs at the branch target; same insns, branch polarity flipped)
group: sched-reorg

**The residual** — The game fn is `slus_012_79:0x8005EE58` (16 words). It tests a signed byte counter. Then it either
clears a flag and returns 1, or it decrements, pops a pointer and returns 0. The natural draft is
`if (s->f9d == 0) { s->f9b = 0; return 1; } s->f9d--; ...; return 0;`. The draft has the same 16 insns as the game, but
it first differs at word 3.

Our build tests with the opposite polarity. It lays the decrement arm at fallthrough and the flag arm last. The game
has the flag arm at fallthrough. The slot contents are the same in both. The reproducer is
`tools/probes/levers/repro/jump_else_return.c`. Its cases are a (natural), b (inverted) and c (if/else with a join:
never swapped).

**The mechanism** — The mechanism is not expand and not dbr. It is jump.c. The `.rtl` of the before draft (expand,
do_jump) jumps over the then-arm: `(jump_insn 16 14 18 (set (pc) (if_then_else (ne:SI (reg:SI 83) ...`. The then-arm
is first. The `.jump` (first jump_optimize, toplev.c:3843) has
`(jump_insn 16 14 31 (set (pc) (if_then_else (eq:SI (reg:SI 83) (const_int 0 [0x0]))
(label_ref 28) (pc)))`. The else-arm is first.

The site is jump.c:1796, with the comment `"Look for if (foo) bar; else break;"`. The pattern has a condjump to
label1. In the pattern, range1 ends in a simplejump to label2 (the return label). Also, range2 after label1 ends in a
jump + barrier. For this pattern, the site runs invert_jump (:1830) and splices the two ranges.

The site does not do this on the first iteration (:1808). After reload, the site does this only without delayed
branch (:1815), so jump2 never does it on MIPS. Both arms here end in `return`, so the early-return then-arm always
lands last. The order then survives every later pass unchanged (scratch per-pass marker order: `.jump` to `.dbr` equal).

The delay slots are dbr and identical before/after. The dbr pass steals `move $2,$0` from the target thread for the
bne slot. It fills both `j $31` slots backward. The cc1 program prints all of them inside `.set noreorder` (maspsx
adds nothing).

This is the kit D1-D5 vs 2.95.2 (R1.7-005). Each item gives the status on this lever / battery:
- D1 is the fill_simple backward fill of a jal/branch slot, reorg.c:1998 (dbr_schedule :3579-3580). It is untested
  as a lever. The battery is `repro/reorg_fill_simple.c` a-c and `repro/reorg_eager.c` b (`.jump2` 0 → `.dbr` n
  `(sequence`, slot in noreorder).
- D2 is the slot nop eligibility, mips.md:125-134 define_delay. It is untested as a lever. The battery is
  `reorg_fill_simple.c` d. There, the unfilled jal is printed outside `.set noreorder`, and the nop is maspsx-made (a
  maspsx tell, not a lever).
- D3 is the eager steal / polarity, fill_eager_delay_slots reorg.c:2892 → fill_slots_from_thread :2491. It is untested
  as a lever. The battery is `reorg_eager.c` d (li stolen into the bne slot) vs a (thread heads are loads:
  may_trap_p :2612 bars it).
- D4 is the copy-forward in fill_slots_from_thread (validate_replace_rtx reorg.c:2745). It is untested (not isolated,

  The battery is `repro/jump_crossjump.c` a-c: no merge in any shape (`.jump2` insn count = `.sched2`).
- The block order / polarity (this lever) is proven, jump.c:1796.

**The lever** — The condition is that the game lays the arms opposite to the draft and both arms end in `return`. If
so, invert the test and swap the arms. Write the arm that the game puts at the branch target as the early-return
then-arm (`if (s->f9d != 0) { s->f9d--;
...; return 0; } s->f9b = 0; return 1;`). The file jump.c moves it last.

The file jump.c does not swap an if/else that joins (no return in the arms). Its source order is the layout. Before
you blame dbr, check the `.rtl` vs `.jump` polarity.

**The byte proof** — The proof is the `config/levers.tsv` row `swap-returning-arm`. The file
`tools/probes/levers/swap-returning-arm.before.c` differs from the game at word 3. The `.after.c` file (test inverted,
arms swapped, nothing else) is byte-identical (relocation-masked) under the pinned triple. The result of
`tools/codegen_map.py --check --groups sched-reorg` is proven.
