# C0049 — Counted for vs while (n--): check_dbra_loop reverses a counting-only for to 0, but n-- tests vs a hoisted -1
tags: codegen-map,loop,check_dbra_loop,move_movables,reversal,hoist,biv,count-down · date: 2026-10-02 · phase/task: 1.7/T5 · origin: -

tell: count-down to -1 against a hoisted -1 constant (beqz guard, bne) vs reversed count-down to 0 (blez guard, bnez)
group: loop

**The residual** — The game fn `slus_012_79:0x800474B4` walks `n` links of a list: `p = p->next` n times, then it
returns p. The natural draft `for (i = 0; i < n; i++) p = p->next;` compiles to 8 words, but the game fn has 10 words.
The guard branch is different. The draft tests the counter against 0, but the game fn tests it against a constant -1.
A register holds that constant, and the game fn loads the register once before the loop. The diff starts at word 0.

The reproducer is `tools/probes/levers/repro/loop_hoist.c`. It shows the cc1 `.s` before maspsx, with the same walk at
offset 4.
`hoist_b (for)` → `blez $5 | move $2,$4 | L: lw $2,4($2) | addu $5,$5,-1 | bne $5,$0,L | j $31`.
`hoist_a (while (n--))` → `move $2,$4 | beq $5,$0 | addu $3,$5,-1 | li $4,-1 | L: lw $2,4($2) | addu $3,$3,-1 |
bne $3,$4,L | j $31`.

**The mechanism** — The mechanism is in gcc 2.95.2 `loop.c`, which runs twice at -O2 (`rerun_loop_opt`,
toplev.c:3935). Unroll is off. The census is R1.7-007.
- The draft (`for`): `i` is a biv, and only its increment and its exit test use it. That gives
  `no_use_except_counting` (loop.c:7779-7826), which skips the call/volatile/mem-store limits (:7872-7878). Then
  check_dbra_loop (:7654) reverses the loop. The `.loop` dump has `Can reverse loop` (:7885) and `Reversed loop`
  (:8162). Pass 2 then sees `Insn 55: possible biv, reg 83, const =-1`, and the test becomes `!= 0`. The test needs
  no constant.
- The lever (`while (n--)`): the test reads the old `n`, and the body keeps `n - 1`. After cse/combine, the loop
  tests the decremented biv against -1. The initial value of the biv is complex
  (`Biv 82 initialized at insn 39: initial value is
  complex`), so there is no reversal. The -1 is a loop-invariant set, and scan_loop/move_movables (:634, :1739)
  hoist it to the preheader. The `.loop` dump has `Insn 16: regno 83 (life 1), move-insn savings 1  moved to 49`
  (:1767, :1780, :1876).
- 2.95.2 vs kit L3 (2.7.2): the reversal here holds with a variable bound and with a call in the body. The repro
  `loop_dbra.c` `dbra_a` (`for (i<n) g();`) gives `Reversed loop`. The cause is that `no_use_except_counting`
  short-circuits the 2.7.2 conditions.

**The lever** — The lever applies to a count-up `for` whose counter only counts. If the game tests against a register
that holds -1, write `while (n--)`. That game code has one `li` before the loop, a `bne` back-edge and a `beqz` guard.
If the game counts down to 0 with a `blez` guard, keep the `for`. The mirror: a game counter that stays count-up
(`slt` vs the bound) means that the body uses the counter. The repros are `loop_dbra.c` `dbra_b` and `loop_giv.c`
`giv_c`.

**The byte proof** — The probes are `tools/probes/levers/while-postdec.{before,after}.c`, row `while-postdec` in
config/levers.tsv. The command `codegen_map.py --check --groups loop` gives `proven`. The after file is
byte-identical, relocation-masked, under psyq4.6/a2.86/G0/O2. The before file does not match, so the lever is not
inert (G45).
