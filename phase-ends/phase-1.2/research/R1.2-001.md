## Findings
1. Ghidra
- Latest stable is 12.1.4 (tag Ghidra_12.1.4_build, ghidra_12.1.4_PUBLIC_20260921.zip). The tag README says "Install JDK 21 64-bit" (Temurin). The master README says JDK 25, which is dev and not the release requirement.
- macOS arm64 is not named in the README. Ghidra ships arm64 natives in recent releases (from my knowledge, not re-verified here), so Temurin 21 arm64 is expected to work. Verify with a smoke test.
- analyzeHeadless (from my knowledge, not re-fetched):
  `support/analyzeHeadless <projDir> <projName> -import <file> [-processor/-loader ...] -postScript Foo.java args -scriptPath <dir> [-overwrite] [-noanalysis]`
  Use `-process <name> -postScript ...` to run on an already imported program. `-readOnly` avoids saving.
2. ghidra_psx_ldr (lab313ru)
- Latest release is 2026.09.03 (2026-09-03): "Add Ghidra 12.1.3". Assets are per-Ghidra-version zips for 12.0, 12.0.1-12.0.4, 12.1, 12.1.2 and 12.1.3.
- 2026.07.08 added a loader option for main RAM size (2/4/8/16 MB).
- Install with File > Install Extensions, using the zip that matches the Ghidra version exactly.
- The README says the loader handles PSX executables, GTE macro segments and PsyQ LIB/OBJ analysis through marker files. It mentions an overlay video tutorial. Whether it loads a raw overlay at an arbitrary base is not stated, so do not assume it. Plan on a manual Ghidra "Raw Binary" import with an explicit base, or a script.
- Signatures are not bundled in the loader README. They live in lab313ru/psx_psyq_signatures: JSON, folders 260, 300, 330, 340, 350, 3610, 3611, 370, 400, 410, 420, 430, 440, 450, 460, 470.
- The README says a version-detection problem is fixed by adding ".0" to the PsyQ version field in the program options. So the version is a loader/program option, apparently detected and recorded there.
- Patch files use the ops `~` (replace), `+` (add), `-` (remove).
- Headless is not documented. It runs as a normal Ghidra loader and analyzer, so analyzeHeadless with `-loader` should work. Test it.
- Auto-apply on import vs script is not confirmed from the README. Check the repo source and wiki.
3. PCSX-Redux
- Binaries are for Windows x64, Linux AppImage and macOS Arm64 (README). GitHub Releases is empty, so it is not pinnable by release. Builds come from the project's CI/dev-build links on the docs site (pcsx-redux.consoledev.net). Pin by build id or commit, or build from source at a commit (macOS needs Xcode and Homebrew deps).
- Flags (from src/main/main.cc): `-no-ui` (text UI), `-cli`, `-run`, `-bios <path>`, `-iso/-loadiso/-disk <path>`, `-loadexe/-exe <path>`, `-dofile <lua>`, `-exec <lua code>`, `-stdout`, `-logfile`, `-webserver`/`-no-webserver`, `-webserver-port <n>`, `-gdb`/`-gdb-port`, `-debugger`, `-fastboot`/`-no-fastboot`, `-8mb`/`-2mb`, `-dynarec`/`-interpreter`, `-softgpu`/`-openglgpu`, `-pcdrv`/`-pcdrvbase`, `-memcard1/2`, `-trace`, `-kiosk`, `-version`.
- Web server (from memory, UNVERIFIED because the docs URLs 404'd): default port 8080, enabled in settings or with `-webserver`. Routes include `/api/v1/cpu/ram/raw` (GET/POST), `/api/v1/cpu/rom/raw` and `/api/v1/gpu/vram/raw`. Execution control is `/api/v1/execution-flow?function=pause|resume|reset|softreset`. Breakpoint endpoints are unknown. For breakpoints and registers, use Lua (`PCSX.addBreakpoint`, `PCSX.getMemPtr`, `PCSX.getRegisters`). The docs have a "Webserver Lua API" section. Run `curl localhost:8080/api/v1/cpu/ram/raw` and check the docs before pinning.
- Lua: console in the GUI, `-dofile`/`-exec` otherwise. Docs sections cover Memory and registers, Breakpoints, Events and PSX binaries.
- OpenBIOS is bundled and is the default if no `-bios` is given. Known compatibility caveats exist but were not retrieved. Commercial games mostly boot, but for oracle fidelity use `-bios` with a real dump (e.g. SCPH1001/5501). Not verified.
4. Ghidra MCP servers (headless-capable)
- pyghidra-mcp (clearbluejar), `uvx pyghidra-mcp <binary>`. Headless via pyghidra/jpype. stdio/SSE/HTTP transports, Docker image, multi-binary projects, semantic search. Best fit with Claude Code.
- bethington/ghidra-mcp: a large GUI-plugin server with about 272 tools and full write access. It also advertises a headless mode.
- LaurieWired GhidraMCP: the original, GUI-plugin plus bridge. It needs the Ghidra GUI running, so it is not headless.
- Other "Ghidra Headless MCP" and ghidra-retro-mcp servers exist. Not vetted.
