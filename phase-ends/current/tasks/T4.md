Decisions:
- binding: the work is split between host and volume. /work has no .git, `dc.sh run` passes no stdin, and host `.run/` is never synced. So the steps that commit or write tracked config run on the host, and they drive the container through `dc.sh sync`, `dc.sh push .run/waves/<wave>`, `dc.sh run … --in-volume` and a tar pull.
- binding: gate. Precondition: the tree is clean and the wave is not yet gated. A second gate is refused, so the journal never gets duplicate rows.
- binding: scoring follows G50 and is directory-gated. A target dir with neither draft.c nor verdict.json is refused (`missing verdict: <dir>`, rc 2, nothing written). A stray dir is refused too. With no draft.c, the target counts as no-verdict. If draft.c exists, the verbatim grep runs first (G11 pasted asm → plateau, label verbatim), then `reconcile.py <draft> --target` with no apply.
- binding: outcome map. `failed … build-error` is a hash mismatch → plateau (`hash-mismatch <rung>`) when make.<rung>.log shows the compile went through and the `.bin.bad` rename happened. A real compile, assemble or link error → compile-error. The agent's verdict.json is only a claim (`claims: k of D agree with the score`); `gate.json` per dir holds the score.
- binding: banking is per destination unit (DK-36). The tool snapshots src/config/include, splices each member with `reconcile --apply`, and runs one propagate.scratch_build for ONLY=<alias>. It compares the sha1 with config/check.<alias>.sha. On green it writes `banks/<k>.tar` plus a `banks.tsv` row; on red it restores the files and marks the members failed. The host then extracts each tar in k order and commits it with `commit_task.sh <wave> "bank <alias>/<unit>: …"`. That way every intermediate commit is the exact state that was hashed. A final commit records the gate line in journal and waves.
- binding: after any bank, gate runs `census.py --check`, `twins.py` (G46), and `propagate.py --dry-run --family` for each banked fn that is a registered exemplar. A banked fn with exact-dup siblings that is not registered prints `propagation candidate: … unregistered`.
- binding: `fleet <wave>` requires a clean tree with every bank commit as an ancestor of HEAD. It then runs sync and fleet_check.sh, and on green it writes `83/83@<short HEAD>`. `close` refuses in three cases: no gate; a fleet commit that does not descend from every bank commit; or any banked row whose note lacks `strip:` (`unharvested`). On pass it sets closed and `done:<n> notes` and commits waves and journal.
- binding: `harvest --fn A:S --note T [--lever ID --stripped P]` is refused for an unbanked fn, an unresolved lever, or a note over 120 chars. A credited lever needs `strip: differs` (scratch build of the unit with the fn replaced). `strip: identical` means the lever is inert, and the credit is refused (G45). Notes take the form `strip:ok:<ID> …` or `strip:none …`.
- binding: `--check` exits 0 iff the control is ok and the ledgers parse. A `k of n` line with k < n is reported but does not fail the exit, so an open wave does not make the scanner flap. The milestone reads the text lines.
