## Rationale
- Five tasks, isolate-then-fan-out (house rule §5): T1 toolchain in the image; T2 the generator; T3 the Makefile proven on 4 pilots (exe + one overlay per route R1/R2/R3); T4 the whole fleet + `make expected` + the clean fleet check; T5 promote the contracts and write the ops docs. T3 before T4 because a Makefile bug multiplied by 83 is 83 failures with one cause.
- splat64 pinned in the image at 0.41.0 (kit-proven on PSX) via a venv `/opt/splat` in `tools/docker/Dockerfile`, versions in `docs/ops/docker-host.md`; T1 may take a newer release only if 0.41.0 fails on this fleet, recorded under Deviations with the failure. In the image, not a repo `requirements` file: the build host is the pin boundary (M10).
- Configs: `tools/splat_gen.py` writes `config/splat/<alias>.yaml` (tracked) from `config/loadmap.tsv` + `config/boundaries.tsv`. They are onboarding files in the kit's sense (`new_binary.sh` writes once, later phases hand-edit subsegments when C lands), so the generator refuses to overwrite an existing YAML without `--force`, and `--check` asserts the *cuts* (every forced boundary of the binary is a subsegment start or end; segment set covers [0, size) exactly; base/vram equal the load map) rather than byte-equality of the file. This keeps H1 honest without forbidding the 1.8 campaign's hand edits.
- Alias rule (decided): lowercase path, `/` and `.` → `_`, `.bin` suffix dropped: `SLUS_012.79` → `slus_012_79`, `BIN/E00.BIN` → `bin_e00`, `PSX/BIN/ST1.BIN` → `psx_bin_st1`, `PSX/DATA/MAP.BIN` → `psx_data_map`. Collision check in `--check`.
- Units cut at forced boundaries: exe → header `bin` [0,0x800) + one asm subsegment per `lib-object` extent and per gap between them inside .text, with each `jtbl` that falls in a unit's data island emitted as a `.rodata` subsegment named like its code unit (kit migrate rule, cookbook :340-371) when it is single-referenced, else a `data` subsegment; [text_end, end) per `data-island` rows as `data`/`bss` from the header. Overlays → one asm unit per [base, text_end) + `jtbl` rodata pairing + `data` for the island. Finer per-function cuts are 1.5/1.8 work; 1.3 cuts only where 1.2 proved a boundary.
- `BIN/WEP_S00.BIN` (28 B, no base): one `bin` segment, vram 0, alias `bin_wep_s00`, a comment line naming why; it is in N and is hash-checked like the rest. Not a guessed base (G68 / T4's "ranked none, never a guessed base").
- Size % 4 ≠ 0 (17 rows): kit pattern `[floor4, bin, trailing]` with the bin asset assembled at `.data` alignment 1 and the ≤ 3-byte trim gated on `size(build) > size(target)`; never a blanket trim.
- Hash check inside the build (milestone wording): each `build/<alias>.bin` rule ends with `sha1sum -c config/check.<alias>.sha`, so a wrong byte fails `make build`. Exe output is the full PS-X EXE file (header bytes come from the header `bin` segment; no header synthesis now). `make expected` = copy of the green `build/` outputs to `expected/` (the asm-differ baseline for 1.4+), refused unless the build was green.
- Clean fleet check `tools/fleet_check.sh` (container): `rm -rf build asm` (named paths only; never `git clean -x`, G18) → `make extract` into `.run/` → split all → `make -j build` → counts `check.*.sha` passing against N from `config/loadmap.tsv` and prints `<k> of <N> byte-identical`; exit 0 iff k = N = 83 and the number of `check.*.sha` files is N. N comes from the load map, never from the check files (the denominator is not self-reported). Parallel `-j$(nproc)` from the start (C0004).
- gp: PsyQ binaries often address small data through `$gp`. T2 reads the exe's `lui gp`/`addiu gp` startup pair and sets splat `gp_value` for the exe if present; overlays that use `$gp` share the exe's value. Recorded in `docs/memory-map.md`. Assembled with `-G0` either way (all-asm; the relocations come from the `.s`).
- Contract promotion: `pending:` → `required:` only after the fleet is green (T5), because a `required:` source that does not resolve fails `audit_public.py` for every later commit.
- Every task `effort: medium` (preset pro, hard rung none); every task loops build/test or touches several files → `coder: opus55`. No `review: yes`: every verdict is a hash.
- Rejected: hand-written YAML per binary (83 hand edits, no check); one Makefile rule per binary hand-listed (generated `build/overlays.mk` from the configs instead); symbol-name import from the Ghidra delta (names are a readability/1.10 concern and would put PsyQ-signature names into 83 configs before they are needed); building on the Mac host.

## Risks
- splat 0.41.0 mis-splits the PS-X EXE header or a data island (header offset vs vram, `ALIGN(.,4)` padding) → T3 pilots catch it on the exe first; levers: header as `bin`, data islands as `data`, the gated ≤ 3-byte trim. Detection: T3's in-rule sha1.
- spimdisasm drops or misplaces jump tables in overlays whose tables sit in a contiguous island → `data` subsegment fallback (all-asm needs no migration to match bytes). Detection: T3/T4 byte diff at a `jtbl` offset.
- `$gp`-relative code without a correct `gp_value` assembles to wrong offsets → T2 records gp from the exe startup; detection: T3 exe pilot diff in a `lw/sw ..(gp)` word.
- A ranked (unproven) base is wrong for some overlay → splat emits symbolic `%hi/%lo` and `jal` against the assumed vram, which reassembles to the same bytes only if vram equals the true base. Detection: that overlay alone fails in T4; lever: check its `boundaries`/ranking evidence, then a `prove_load.sh` run; a base change goes through `config/loadmap.evidence.tsv` + `tools/loadmap.py` (regenerated), recorded under Deviations.
- Container extract differs from the host extract (disc volume, dumpsxiso paths) → T1 compares the manifest sha1 first.
- `audit_public.py` does not expand globs → per-file `required:` lines (T5); a `required:` that does not resolve breaks every later audit, hence promotion last.
- A tracked YAML or doc carries game-derived text (labels from Ghidra names, strings) → names are `<alias>_<hex>` only; detection: `audit_public.py` in every verify.
- Fleet check exceeds one tool call → `run.sh --bg/--wait`; detection: T4 runtime record.
