  - canonical type layer (G62, DK-65): one canonical header from the first bank, grown one byte-proven field at a time; a draft with a duplicate shape definition or a raw address cast is refused; struct spelling is not always byte-neutral in gcc 2.7.2, so types enter per access under the byte gate, never by blanket rewrite.

## Rationale
- Order: T1 (twins), T2 (types), T3 (carves) are independent instruments; T4 (propagate) needs T2's header and T3's carve of st8; T5 (reconcile) needs T2 (canonical-signature rung) and T3 (carve rung); T6 (draw filter) consumes T1's twin table; T7 wires and verifies. T1–T3 can run in any order; the router runs them in id order.
- Family choice e322 is forced by the evidence: it is the only exact class with a banked member. A larger family would need a new hand match first; the milestone asks for "one hand-matched family", and e322 proves the mechanism end to end (carve, shared body, gate per member, fleet run). The fail-closed proof is a planted bad member, not a bigger family.
- Shared body form: the body lives once as C in `src/shared/<exemplar>.inc.c`, included by each member unit with the member's name supplied by a one-line `#define` before the include; no macro bodies (GENERATION_PLAN readability constraint: "shared bodies as C"). The 1.10 readability census counts macro bodies, not a name `#define`.
- Registry `config/families.tsv` keyed by exemplar and member `alias:start` (G41); propagation writes nothing unless every member's dry-run build is hash-equal (fail-closed); real apply then requires a clean fleet_check before commit (DK-5 "a gate verifies one binary but propagation writes N").
- Twin band "known exact pair" = every unordered pair inside a dup_census exact class (Σ C(n,2)); the band must place each at distance 0 and rank 1 among that fn's twins. Random-pair control: seeded sample from different exact classes, band hit rate printed and bounded (≤ 2%), mirroring dup_census's near control (seed 1505). Twins reuses dup_census's `exact_key`/`near_word` masking (tools/dup_census.py:134,140) rather than re-implementing masking (G33).
- Carves: splat_gen has no unit end column; a single-function unit today runs to the next cut. T3 adds an optional `end` column to config/c_units.tsv (a closing cut), so a carve isolates exactly the functions it names; existing 4 rows keep empty `end` (behaviour unchanged). `carve.py` = add/narrow row → `splat_gen.py --force --only <alias>` → INCLUDE_ASM skeleton for new unit → `make build ONLY=<alias>` → hash; on any failure restore the row and yaml (revert-on-fail). Control: a planted carve inside a lib-object span must be refused (splat_gen.py:178-180) and leave the tree unchanged.
- Data-in-text spans (20) stay as asm; promoting them to boundaries.tsv rows is not needed by any 1.6 milestone clause; it becomes a carve when a 1.8 wave touches a binary that has one.
- Draw filter derives every refusal from evidence each run (G31: a stored exclude list goes stale; BFM 88 of 107 stale). No exclude list file. Reasons: `banked`, `not-a-census-start`, `no-asm`, `out-of-range`, `lib`, `data-in-text`, `pin-unproven` (module family not yet probed: E, KOF, WEP, WEP_S, RES, MISC per 1.4/T7 note; refused until a probe row for that family exists in config/probes.tsv), `has-banked-twin` (routes to propagate, not a draft), `open-twin-sibling` (G46: second member of an open twin cluster in one draw), `switch` (fn owns a jtbl row; C units do not yet carry jtbl rodata). Engineering default: refuse and print, so 1.8's manual wave sees exactly what is excluded and why.
- Canonical header: `include/dc2.h` (types only, included by `include/common.h` users explicitly). T2 lifts only shapes already used by banked units and needed by T4 (`Obj` from st6), each under the byte gate. `types_check.py` scans `src/**/*.c`: duplicate = a `struct`/`typedef struct` in src whose tag or member layout equals one in `include/`, or the same shape defined in ≥ 2 units; raw address cast = a cast of an integer literal ≥ 0x80000000 to a pointer. Control = two planted files in `.run/types_fixture/` that must be refused.
- Reconcile proof: the standalone match comes from `tools/probe.py --pinned <name>` on a new config/probes.tsv row (a small open game fn, ≤ 0x80 B, in st2/st6/st9/exe, pinned modules only); `reconcile.py` banks it into its real unit with the body text hash unchanged before/after (= "without redraft"). Known-true control: an existing banked body (func_80037E18) in a scratch copy of its unit with a planted conflicting declaration must bank via the declaration-sync rung. Directory gate counts every draft in `.run/reconcile/drafts/` (G50).
- Scanners: each new tool gets a config/scanners.tsv row in its own task (denominator + control regex, G70), so S grows from 10 to ≥ 16 (twins, types, carve, propagate, reconcile, draw_filter).

Each task documents its tool in docs/ops/decomp-environment.md (new `## The multipliers (Phase 1.6)` section after :393); T7 adds one combined card row `multipliers` pointing there and trims elsewhere to fit. The card change waits for T7 to avoid six trims; a deviation from per-task H7 recorded here.
