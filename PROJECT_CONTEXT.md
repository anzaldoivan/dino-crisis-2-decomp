## Project Overview

Dino Crisis 2 (Capcom, 2000; USA SLUS-01279) is an action-survival game from Capcom's survival-horror line (Shinji
Mikami producing), on a single disc. It has no public matching decompilation; prior community work is a recompilation and a
randomizer, which carry no evidenced symbols and feed no matching work. This project produces the first byte-identical
C source for it, public from the first commit, with every number it publishes generated by the build.

### Project Assumptions

- The medium (verified locally 2026-09-30): Track 1 ISO9660 (mode 2) + Track 2 CD-DA. `SYSTEM.CNF` boots
  `SLUS_012.79` (591,872 bytes). 685 directory entries: 105 `.BIN` (89 under `/BIN`, e.g. `DBMODULE`, `DM_*`, `AT_EDIT`;
  15 under `/PSX/BIN`, e.g. `ST0`–`ST*`, `AREA_JMP`, `LOGO`), 415 `.DAT`, 89 `.DBS`, plus `.TEX` `.PXL` `.XAS` `.STR`
  `.TRG`. The `.BIN` files are presumed code overlays (stage and module) until Phase 1.2 proves load addresses; the
  `/BIN` `DM_*`/`DBMODULE`/`AT_EDIT` names suggest shipped debug/edit modules — naming evidence if confirmed.
- SDK evidence: the executable carries "Library Programs (c) 1993-1997 Sony Computer Entertainment Inc." — PsyQ 4.x era
  libraries; the compiler family is a candidate set (GCC 2.7.2-era cc1 builds) until Phase 1.4 pins it.
- One developer, one Mac (arm64, macOS), one agent carrying the work between gates; contributors bring their own dump.
- The dump lives outside the repo (`/Users/Shared/GameInputs/dino-crisis-2/usa/`), machine-local, never committed.

## Lessons Learned / Known Risks

Carried from Brave Fencer Musashi's retrospective (`anzaldoivan/BFM-decomp`, `docs/retrospective.md`) and the kit's
failure museum:

- Almost every recorded wall was one of the project's own instruments — coverage assertions and the differential
  harness are built at 0% (Phase 1.5), each scanner checked against a known-true case.
- Integration, not idioms, is the bottleneck once cracking is systematic — the banking layer (1.6) precedes the waves.
- A wrong compiler era or a silent assembler default produces systematic near-misses — the pin is by evidence (1.4),
  and the compiler's own source is read before any "unsteerable" verdict.
- "Whose object is this?" before "which pass emitted this?" — Sony library objects are censused, not cracked.
- Structural decisions get more expensive as matched work accumulates — segment at the forced boundaries before any C.
- A fresh session misreads a compressed hand-off — hand-offs are replayed, never summarised.
- Model-drafted outward text costs goodwill; model-guessed names damage a decomp silently — both forbidden.
- Budget: a Pro plan. Free (local, deterministic) work before paid work; waves sized to the budget.
- Disk: 28 GB free at generation (87% used); scratch capped at 25 GB, warned at 20 GB.

## Project Philosophy

**North Star:** every binary on the Dino Crisis 2 USA disc rebuilds byte-identical from readable C, and a stranger with
their own dump can prove it from the README alone.

Tooling first, then the campaign: each multiplier (census, propagation, reconcile, codegen map, permuter) is built
before the work it multiplies. The byte gate is the only claim. Readability is enforced at bank time, not afterwards.
Evidence over recall: every address, name and pin carries its basis.

## Core Logic / Strategy

The pipeline every matching decomp of this generation runs: extract (deterministic, manifest of hashes) → split (splat,
per-binary layout config, curated symbol file) → build (modern cpp → pinned vintage cc1 → assembler shim → mipsel
binutils) → whole-binary hash check inside `make build` → the campaign machinery (corpus oracle, signatures and twin band,
dedup propagation, reconcile ladder, carve chain, draw filter, codegen map, permuter, cards, lanes, waves).

### Component Inventory

Extractor + manifest · format notes · load-map tool · split configs per binary (main exe + every code overlay) ·
Makefile pipeline and per-binary contracts · probe harness · corpus oracle and census · differential harness · signature
and twin tooling · dedup registry · canonical type file · carve tools · draw filter · codegen map · permuter · plateau
classifier · cards/lanes/waves · contract script · progress publisher · rename-coverage scanner.

## Safety / Guardrails / Error Handling

- The ROM firewall (`tools/audit_public.py`, the no-ROM CI) from commit one; no private exemption.
- The byte gate is the only definition of done; no unmatched C in a default build.
- AI conduct: names only with evidence; outward text (issues, PRs, releases, messages) written by a person; no
  automated traffic against community infrastructure; every change justifiable from the record.
- Irreversible operations are rehearsed on a scratch copy with a proof that asserts presences, not only absences.
- Never `git clean -x` (it deletes the extraction and scratch).

## Testing & Validation Strategy

The clean fleet check (`clean → extract → build` over every onboarded binary, hash-checked) is the test. Every scanner
prints its denominator and passes a known-true control; the differential harness runs on a schedule; CI proves
everything that needs no game (the ROM audit, compiling every translation unit with the pinned toolchain), and
byte-identity is proven locally with the dump and recorded.

**Pass criteria:** N of N byte-identical from a clean rebuild; the ROM audit green; the phase's `verified by:` commands green.
